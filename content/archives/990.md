今天，我开始将我目前使用电脑的Windows 2000 Server操作系统升级到了Windows Server 2003，然而我没有想到的是，升级过程很不顺利。

Windows 2000 Server我使用了有6年时间，还是很怀念这个操作系统，不过由于我目前使用的大多数服务器操作系统已经都用Windows Server 2003了，因此我也有必要将我个人使用的电脑的操作系统也升级到Windows Server 2003.另一个升级的原因是微软对于Windows 2000的支持越来越差，微软新出的很多软件（如新版MSN）都无法在Windows 2000上安装使用，综合这些原因，我于是计划将个人电脑的操作系统升级到Windows Server 2003.

为了验证从Windows 2000 Server升级到2003的效果，我先将自己公司的电脑操作系统升级了一次。在Windows 2000 Server系统中，运行Windows Server 2003的安装程序，选择默认的升级操作，用了大概一个多小时时间，很顺利的升级到了2003的操作系统。在新操作系统下，我将主题和菜单都设置为“Windows经典”，发现界面和Windows 2000 Server几乎一摸一样，在操作习惯的继承上看很不错。打了Windows 2003 SP2的补丁后，IE6也变成了SP2，从界面上看和Windows 2000的IE6有很微小的差异。

由于在公司的电脑操作系统顺利升级，因此我也立刻计划将家中的电脑操作系统也进行升级，然而晚上运行升级程序时，总是提示有不兼容的程序，我卸载了WinZip和Daemon Tools后才能运行升级程序。

不料升级程序复制完后重新启动，在进入Windows 2003安装界面前就出现了蓝屏，于是我按F8从安装模式启动，中间提示加载一个名为SPTD.SYS的SCSI驱动时我取消加载，终于调出了Windows 2003的界面，这时系统提示无法在安全模式运行Windows安装程序，然后就退出系统了。

这时我发现自己升级操作系统陷入了完全失败的境地。旧的Windows 2000系统无法恢复，新的Windows 2003则无法进入安装界面，我尝试手动删除那个SCSI驱动程序，依旧是蓝屏，在折腾了一个多小时之后，操作系统还是没有升级程序。我只好重新安装一个新的Windows 2003操作系统。

安装全新操作系统还是很顺利的，很快就安装好了，但是因为升级系统的失败，我需要将原有操作系统的程序全部重新安装，包括银行的数字证书、邮件帐号等等，实在是痛苦。

看来如果电脑安装的软件和驱动较多的话，升级Windows 2003系统也存在很大的风险，因此升级前一定要做好备份工作，否则出现了旧系统还原不了，新系统进不去的情况就很麻烦了。
